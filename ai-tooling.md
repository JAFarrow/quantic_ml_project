# AI Usage

AI tools were utilized across the stack, mostly in the form of ChatGPT and OpenCode utilizing GPT-5.1 Codex mini as its' model. 

### Exploratory notebook and EDA

ChatGPT was consulted as to what I should be looking out for as I explored across the data to better inform my preprocessing efforts. Some code snippets were also generated, in particular the process of string column exploration. 

Overall, it proved to be useful and some of the recommendations were outside of the scope that was instructed in the Intro to Machine Learning module which furthered my understanding of EDA.

### Model evaluation and production model training

ChatGPT assisted in scoping out the neccesary stages of model evaluation and OpenCode proved useful in laying out the skeleton for preprocessing, evaluation and model training after planning out the necessary requirements.

Both ChatGPT and OpenCode were useful and accelerated this phase of the project, although some issues arose with preprocessing where some requirements were not catered for or the code generated introduced bugs and inconsistencies when integrated further down the line with evaluation and training. 

### Flask backend

With some experience in flask backends, I decided to write out the majority of it. ChatGPT had some contribution, for example recommending marshmallow for verifying incoming data and surfacing any issues back to the client. 

### React frontened (NOT PRESENT IN REPO, see https://github.com/JAFarrow/quantic_ml_frontend)

Having little experience with frontends, especially in React, I leaned heavily on OpenCode to generate the bulk of the code. 

In general, it was a painless experience, although a good chunk of time was spent in planning mode going back and forth over the requirements. Backend integration was suprisingly easy after documenting the API contract and feeding it to the model at the beginning of planning.
